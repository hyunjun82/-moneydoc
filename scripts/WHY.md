# 사고 기록 — 규칙이 왜 생겼는지

CLAUDE.md 는 "무엇을 하라" 만 적는다. "왜" 는 여기 있다. 규칙을 지우거나 바꾸기 전에 읽는다.
새 사고가 나면 여기에 한 줄 추가하고, CLAUDE.md 는 건드리지 않는다.

---

## 왜 같은 글을 세 번 만졌나 (2026-09-04)

글을 쓰고 → 나중에 문제를 찾고 → 다시 고쳤다. 원인은 하나다.

**검사가 "쓴 것" 만 보고 "안 쓴 것" 은 안 봤다.**

`factcheck` 는 글에 적힌 숫자가 근거에 있는지, 인용이 원문 그대로인지 봤다.
그런데 *근거에 답이 있는데 글이 회피했는지* 는 아무도 묻지 않았다.

| 놓친 것 | 근거에는 있었다 |
|---|---|
| payday "언제 들어오나요" → "사람마다 달라요" | 고용24 안내 "통상 실업인정을 받은 다음 날에 지정 계좌로 입금됩니다" |
| other-activity "취업특강 몇 번" → "안내받아요" | 노동부 상담 "취업특강 3회, 직업심리검사 1회" |
| round-1·round-4 "구직활동 몇 번" → "사람마다 달라요" | 고용24 매뉴얼 "2~4차 4주 1회, 5차부터 2회" |
| total "4개월은 120일" → 150일 금액을 적음 | 엔진이 두 값을 다 갖고 있었다 |

지금은 `answer-check.mjs` 가 **빌드 시점에** 넷을 다 잡는다.

**그리고 구멍을 이론으로 찾지 않는다.** `selftest/mutate.mjs` 가 결함 20종을 글에 심고
파이프라인이 몇 종을 잡는지 잰다. 검사기를 고치면 이 시험부터 돌린다. 지금 20/20.
이 방식으로 실제 구멍 둘을 찾았다.

- 소제목 질문 검사가 "정리·방법·조건·기준·단계" 를 통과시켰다. "대기기간 7일 정리" 가 질문으로 취급됐다.
- 렌더 사고 검사가 `>undefined<` 만 봐서 문장 속에 섞인 `undefined` 를 놓쳤다.

## 라이브까지 나갔던 오류 (2026-09-04 전수 검토에서 발견)

| 오류 | 원인 |
|---|---|
| "월 200만만원" 이 4편 64곳 | `man()` 이 이미 "200만" 을 돌려주는데 스펙이 "만원" 을 또 붙였다 |
| total "4개월=120일" 에 150일 금액 | 엔진 호출 인자(`insuredYears: 1`)와 설명("1년 미만")이 어긋났다 |
| amount 상한 도달 월급 45,400원 오차 | 엔진은 월급÷30 인데 그 문장만 30.4 를 썼다 |
| confirmation 에 10일 기한·과태료 없음 | 근거에 있었는데 안 읽고 썼다 |
| voluntary "시행규칙 목록에 17가지" | 별표2 항목은 13개 + 포괄 1개. 17은 우리 표의 행 수 |

**엔진 기준**: 평균임금은 `monthlySalary * 3 / 90`, 즉 **월급 ÷ 30**. 글에서도 30으로 나눈다.

## 제목 규칙이 왜 이렇게 됐나

| 규칙 | 사고 |
|---|---|
| 제목 앞부분은 실측 검색어 | "노동청 진정과 함께 가는 법" 을 지어냈다. 데이터에 0건 |
| 뒷부분도 본다 (사람이) | 앞부분만 검사했더니 뒤에 "내 월급이면 얼마인가요"(0건)·"1일 수령액"(0건)이 들어가 라이브까지 갔다 |
| 기계는 1인칭·클릭베이트만 막는다 | 낱말 단위로 코퍼스와 대조했더니 경고가 30건 쏟아졌고 대부분 "월급별" 같은 평범한 말이었다. 시끄러운 경고는 무시된다 |
| `review.titleKeyword` 필수 | 그래서 사람이 근거를 대게 한다. 기계는 그 말이 코퍼스에 있는지만 확인한다 |
| 어색한 우리말도 본다 | 62편 중 30편이 비문·반말 종결·낱말 겹침·명사형 종결이었다. 검색어만 보고 우리말은 안 봤다 |

## 글 구조 규칙이 왜 이렇게 됐나

| 규칙 | 사고 |
|---|---|
| 정부 브리핑은 연도를 본다 | 2022년 브리핑의 "4차부터 2회" 를 현행처럼 썼다 |
| 계산기 버튼은 계획과 일치 | lint 가 calc 를 강제해 25편 전부에 붙었다 |
| 링크는 계획서와 대조 | 최소 개수를 두면 난발. `links: [{to, why}]` 와만 맞춘다 |
| 계획한 시각 장치만 | 표 개수를 강제하니 억지 표. 허브는 **구조 참고지 시각화 복사 대상이 아니다** |
| 빵부스러기는 주제 구조 | `홈 › 정부지원금 › 실업급여` 로 남아 있었다 |
| 글자수·표·각주 개수는 **세지 않는다** | 세니까 군더더기가 생겼다. 답의 길이는 키워드마다 다르다 |
| 렌더러가 버리는 값이 없어야 한다 | 표 행의 `link` 와 `p` 블록의 `link` 가 조용히 사라진 채 배포됐다. 지금은 lint 가 막는다 |

## 훅이 왜 이렇게 생겼나

- 예전엔 `push-changes.bat` 만 봐서 `git push` 를 직접 치면 한 번도 안 돌았다.
- 셸 파이프(`| tail`)를 써서 이 환경(cmd.exe 없음)에선 실행 자체가 안 됐다.
- 훅은 명령 실행 **전** 에 돈다. `git add 파일 && git commit` 이면 스테이지가 비어 있어 통과했다.
  그래서 명령줄 토큰을 경로로 읽어 작업 트리 변경과 맞춘다.
- 히어독 커밋 메시지 안의 "commit -a" 같은 글귀를 플래그로 오인했다. 본문은 검사에서 뺀다.
- 실측 13경로: `selftest/hook.mjs`.
