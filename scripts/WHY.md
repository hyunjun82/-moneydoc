## 왜 같은 글을 세 번 만졌나 (2026-09-04)

글을 쓰고 → 나중에 문제를 찾고 → 다시 고쳤다. 원인은 하나다.

**검사가 "쓴 것" 만 보고 "안 쓴 것" 은 안 봤다.**

`factcheck` 는 글에 적힌 숫자가 근거에 있는지, 인용이 원문 그대로인지 봤다.
그런데 *근거에 답이 있는데 글이 회피했는지* 는 아무도 묻지 않았다.

| 놓친 것 | 근거에는 있었다 |
|---|---|
| payday "언제 들어오나요" → "사람마다 달라요" | 고용24 안내 "통상 실업인정을 받은 다음 날에 지정 계좌로 입금됩니다" |
| other-activity "취업특강 몇 번" → "안내받아요" | 노동부 상담 "취업특강 3회, 직업심리검사 1회" |
| round-1·round-4 "구직활동 몇 번" → "사람마다 달라요" | 고용24 매뉴얼 "2~4차 4주 1회, 5차부터 2회" |
| total "4개월은 120일" → 150일 금액을 적음 | 엔진이 두 값을 다 갖고 있었다 |

지금은 `answer-check.mjs` 가 **빌드 시점에** 넷을 다 잡는다.

**그리고 구멍을 이론으로 찾지 않는다.** `selftest/mutate.mjs` 가 결함 20종을 글에 심고
파이프라인이 몇 종을 잡는지 잰다. 검사기를 고치면 이 시험부터 돌린다. 지금 20/20.
이 방식으로 실제 구멍 둘을 찾았다.

- 소제목 질문 검사가 "정리·방법·조건·기준·단계" 를 통과시켰다. "대기기간 7일 정리" 가 질문으로 취급됐다.
- 렌더 사고 검사가 `>undefined<` 만 봐서 문장 속에 섞인 `undefined` 를 놓쳤다.

2차로 12종을 더 심어(총 32종) 구멍 다섯을 더 찾았다.

- `check-outline`(mustCover 대조)이 "느린 검사" 뭉치에 있어 `--quick` 에서 통째로 빠졌다.
  **훅이 `--quick` 으로 돈다.** 그래서 mustCover 위반이 커밋을 그냥 통과했다. 빠른 경로로 옮겼다.
- 두 글이 같은 제목이어도 아무도 안 봤다.
- 회피 답 검사가 본문 소제목만 보고 **FAQ 는 안 봤다**.
- 한 글에 같은 소제목이 두 번 있어도 통과했다 (목차·앵커가 깨진다).
- https 검사가 '단계 카드' 링크만 봤다. 메모·표·문단·관련글의 링크는 안 봤다.

3차로 16종을 더 심어(총 48종) 구멍 다섯을 더 찾았다.

- 단위 목록에 **`퍼센트` 가 빠져** "65퍼센트" 가 단위 없는 숫자로 새어 나갔다. 게다가 "절반 표기"
  허용(3.595% ← 1만분의 719)이 값 크기를 안 봐서, 근거의 "100분의130" 을 만나 65% 가 통과했다.
  절반 표기는 10% 이하에만 쓴다.
- `reuseEvidence` 로 근거를 빌려 쓰면 **자기 brief 의 출처 수(12)만** 봤다. 원본이 14인데 13으로
  줄어도 통과했다. 이제 원본 brief 수와 맞춘다.
- **반말 종결**(~한다·~된다)을 아무도 안 봤다. 합니다체만 막고 있었다.
- **계획서의 소제목 목록과 글의 소제목**이 어긋나도 아무도 안 봤다. 검사를 넣자 실제로 6편이
  어긋나 있었다(계획서가 단일 진실 원천인데 글만 고치고 계획서를 안 고친 것).
- 같은 문장이 **한 글 안에서** 두 번 나오는 경우. 중복 검사가 글 사이만 봤다.

이 과정에서 검사기가 아니라 **시험이 틀린 경우**도 셋 나왔다. 히어로 카드는 OG 이미지에만 들어가
"7을 14로" 같은 의미 뒤바뀜을 기계가 못 가린다(글 어디에도 없는 숫자만 잡는다). 돌연변이가 엉뚱한
규칙에 잡혀 가짜로 통과한 것도 있었다(반말 시험 문장에 합니다체가 섞여 있었다). 시험도 의심한다.

## 훅이 왜 이렇게 생겼나

- 예전엔 `push-changes.bat` 만 봐서 `git push` 를 직접 치면 한 번도 안 돌았다.
- 셸 파이프(`| tail`)를 써서 이 환경(cmd.exe 없음)에선 실행 자체가 안 됐다.
- 훅은 명령 실행 **전** 에 돈다. `git add 파일 && git commit` 이면 스테이지가 비어 있어 통과했다.
  그래서 명령줄 토큰을 경로로 읽어 작업 트리 변경과 맞춘다.
- 히어독 커밋 메시지 안의 "commit -a" 같은 글귀를 플래그로 오인했다. 본문은 검사에서 뺀다.
- 실측 13경로: `selftest/hook.mjs`.

## 2026-09-06 · 고리를 사람 없이 한 바퀴 돌려 보니 (startup)

쓰기 → 검토 → 고치기 ×3 → 기록 → 게이트를 사람 개입 0으로 돌렸다. 사실·근거는 버텼다.

   B등급이라 FAIL 이 아니었고, 기록 담당이 "다른 글도 그렇다" 며 넘겼다.

칩 큰 글씨 "끊겨요 / 개업일부터" 도 사장님이 잡았다. 서술어가 큰 글씨로 들어가면 뜻이 잘려 읽힌다.
→ lint 가 칩·카드 big 에서 서술어를 막는다. 숫자·명사·예/아니요만.
